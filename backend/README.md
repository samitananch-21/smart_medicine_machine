# PharmaCare+ demo backend

REST API + SQLite ใช้ Python 3.9 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม เหมาะสำหรับสาธิตบน Mac และแอป Flutter ในเครือข่ายเดียวกัน การจ่ายเงินทุกออร์เดอร์เป็น **การจำลอง** (`payment_mode: demo`) ไม่ได้ตรวจสอบเงินจริงหรือสั่งตู้จ่ายสินค้า

## เริ่มใช้งาน

รันจากโฟลเดอร์โปรเจกต์:

```sh
python3 backend/server.py
```

API อยู่ที่ `http://127.0.0.1:8765/api` ทดสอบด้วย:

```sh
curl http://127.0.0.1:8765/api/health
```

เปิดไฟล์ `backend/data/demo_credentials.txt` บนเครื่องเพื่อดูบัญชีแอดมิน (`username: admin`) และรหัสผ่านสุ่ม ไฟล์นี้สร้างครั้งแรกด้วยสิทธิ์ `0600` ไม่พิมพ์รหัสผ่านลง server log และไม่ถูก commit ขึ้น Git เซสชันหมดอายุใน 8 ชั่วโมง และต้องล็อกอินใหม่หลังรีสตาร์ตเซิร์ฟเวอร์

ข้อมูลสินค้าถูกนำเข้าจาก `backend/seed_products.json` **เฉพาะครั้งแรก** หลังจากนั้นการแก้ราคา สต็อก สินค้า และออร์เดอร์เก็บใน `backend/data/demo.sqlite3` และยังอยู่เมื่อปิด–เปิดใหม่ การแก้ seed หรือข้อมูล Flutter จึงไม่เขียนทับข้อมูลในฐานข้อมูลที่ใช้แล้ว ให้แก้ผ่านหน้าแอดมิน

## ใช้โทรศัพท์จริง / เครื่องอื่นใน Wi-Fi เดียวกัน

```sh
python3 backend/server.py --host 0.0.0.0
```

ตั้ง `API_URL` ของแอปเป็น `http://<IP ของ Mac>:8765` ตามคำสั่งรัน Flutter ใน README หลัก โทรศัพท์จริงต้องใช้ IP ของ Mac แทน `127.0.0.1` ส่วน iOS Simulator บน Mac ใช้ `127.0.0.1` ได้ อนุญาต Local Network บน iOS และการเชื่อมต่อของ Python ผ่าน macOS Firewall เมื่อระบบถาม

สำหรับ **เว็บ** ที่เปิดผ่าน IP ของ Mac ต้องอนุญาต origin ของหน้าเว็บแบบตรงตัวด้วย เช่นหน้าเว็บอยู่พอร์ต 8080:

```sh
DEMO_ALLOWED_ORIGINS=http://192.168.1.20:8080 python3 backend/server.py --host 0.0.0.0
```

แยกหลาย origin ด้วยคอมมา ค่าเริ่มต้นอนุญาตเฉพาะหน้าเว็บจาก `localhost`, `127.0.0.1` และ `::1` แอป native ไม่ต้องตั้งค่า CORS อย่าเปิดพอร์ตนี้ออกอินเทอร์เน็ต เพราะเป็นระบบเดโม HTTP และ endpoint สั่งซื้อเปิดให้ลองสร้างออร์เดอร์จำลองได้

## API

ทุก path ด้านล่างขึ้นต้นด้วย `/api` และ request body ใช้ JSON:

| Method | Path | หน้าที่ |
| --- | --- | --- |
| GET | `/health` | ตรวจเซิร์ฟเวอร์ |
| GET | `/products` | สินค้าที่เปิดขาย |
| POST | `/orders` | สร้างคำสั่งซื้อจำลองและตัดสต็อก |
| POST | `/admin/login` | `{username, password}` → `{token, username}` |
| POST | `/admin/logout` | ยกเลิกเซสชัน |
| GET / POST | `/admin/products` | ดูสินค้าทั้งหมด / เพิ่มสินค้า |
| PUT | `/admin/products/{id}` | แก้สินค้า พร้อม `version` ปัจจุบัน |
| GET | `/admin/orders` | ดูออร์เดอร์และรายละเอียด |
| PATCH | `/admin/orders/{id}` | เปลี่ยน `pending` เป็น `fulfilled` หรือ `cancelled` |

API ของแอดมินนอกจาก login ต้องส่ง `Authorization: Bearer <token>` เซิร์ฟเวอร์ตรวจสิทธิ์ทุกครั้ง จัดเก็บรหัสผ่านแบบ PBKDF2 พร้อม salt และจำกัดการล็อกอิน 5 ครั้งต่อนาทีต่อ IP

Product fields: `id`, `name`, `detail`, `price_satang`, `image`, `category`, `warning` (nullable), `stock`, `active`, `version` ราคาจำนวนเต็มหน่วยสตางค์ ต้องมากกว่า 0 และไม่เกิน 100,000,000 สตางค์ สต็อก 0–1,000,000 รูปต้องเป็นไฟล์จริงใต้ `assets/images/` ที่แอปมีอยู่แล้ว หากเพิ่มรูปใหม่ ต้องใส่ไฟล์ใน assets และบิลด์แอปใหม่ด้วย

การเพิ่มสินค้าไม่ต้องส่ง `id` หรือ `version` การแก้สินค้าต้องส่ง field ทั้งหมดและ `version` ล่าสุด เพื่อป้องกันเขียนทับเมื่อมีแอดมินคนอื่นแก้ไข หรือมีการสั่งซื้อ/คืนสต็อกระหว่างเปิดฟอร์ม

ตัวอย่างคำสั่งซื้อ:

```json
{
  "request_id": "unique-checkout-id",
  "items": [{"product_id": "p001", "quantity": 1, "unit_price_satang": 2500}],
  "coupon": "WELCOME10",
  "payment_method": "cash",
  "paid_satang": 5000
}
```

เซิร์ฟเวอร์ใช้ราคาในฐานข้อมูลเป็นหลัก ถ้าราคาที่แอปส่งมาเปลี่ยนแล้วหรือสต็อกไม่พอ จะตอบ `409` โดยไม่ตัดสต็อกบางส่วน ปริมาณต่อสินค้า 1–99 ชิ้น ยอดคำสั่งซื้อไม่เกิน 100,000,000 สตางค์ คูปอง `WELCOME10` ลด 10% ปัดครึ่งสตางค์ขึ้น เงินสดจำลองต้องครบยอด และ QR จำลองต้องส่งยอดเท่ากับยอดสุทธิ

`request_id` เดิมพร้อมข้อมูลเดิมจะได้ออร์เดอร์เดิมกลับมา ไม่ตัดสต็อกซ้ำ หากใช้ ID เดิมกับข้อมูลใหม่จะตอบ `409` ทุกออร์เดอร์เก็บชื่อและราคา ณ เวลาสั่งซื้อ การเปลี่ยนข้อมูลสินค้าภายหลังไม่เปลี่ยนออร์เดอร์เก่า การยกเลิกคืนสต็อกเพียงครั้งเดียวและไม่สามารถยกเลิกหลัง `fulfilled` ได้

## ทดสอบ

```sh
python3 -m unittest backend.test_server -v
```

ชุดทดสอบใช้ฐานข้อมูลชั่วคราวแยกจากข้อมูลเดโมจริง ครอบคลุมสิทธิ์แอดมิน ข้อมูลคงอยู่หลัง restart การตรวจราคา/สต็อก การซื้อพร้อมกัน การส่งออร์เดอร์ซ้ำ การปัดส่วนลด การยกเลิก และ CORS
