# PharmaCare+ — ตู้ยาและหลังบ้านเดโม

แอป Flutter สำหรับเลือกสินค้า จัดหมวดหมู่ คูปอง ตะกร้า และชำระเงินจำลอง พร้อมหน้าแอดมินที่เชื่อม REST API และ SQLite บน Mac

## เปิดใช้งานบน Mac

เปิด Terminal ที่โฟลเดอร์โปรเจกต์ แล้วรันหลังบ้านค้างไว้:

```sh
python3 backend/server.py
```

เปิด Terminal อีกหน้าต่างเพื่อรันแอป:

```sh
flutter pub get
flutter run -d chrome --web-port 8080
```

แอปเชื่อม `http://127.0.0.1:8765` เป็นค่าเริ่มต้น ใช้ปุ่ม **สำหรับผู้ดูแล** บนหน้าเริ่มต้น หรือไอคอน **แอดมิน** บนหน้าร้าน เว็บเข้า `http://localhost:8080/#/admin` ได้โดยตรง

บัญชี `admin` และรหัสผ่านสุ่มสร้างครั้งแรกใน [backend/data/demo_credentials.txt](backend/data/demo_credentials.txt) เปิดไฟล์นี้บนเครื่องเพื่อดูรหัสผ่าน ห้ามใส่รหัสผ่านใน source code หรือแชร์ขึ้น Git

## สาธิตให้ดูครบกระบวนการ

1. เข้าแอดมิน แก้ราคา/สต็อก/รายละเอียด/หมวดหมู่ หรือเพิ่มสินค้า แล้วบันทึก
2. กลับหน้าร้าน กดอัปเดตสินค้า เลือกสินค้าใส่ตะกร้า และลองคูปอง `WELCOME10`
3. เลือกเงินสดแล้วกดเหรียญ/ธนบัตร หรือเลือก QR จำลอง จากนั้นยืนยัน
4. เมื่อ API บันทึกสำเร็จ แอปแสดงเลขคำสั่งซื้อและล้างตะกร้า
5. เข้าแอดมินแท็บคำสั่งซื้อ เพื่อดูรายละเอียด เปลี่ยนเป็นจัดสินค้าแล้ว หรือยกเลิกพร้อมคืนสต็อก

ทุกคำสั่งซื้อเป็น **เดโม** ไม่มีการรับเงินจริง ตรวจการโอน หรือสั่งจ่ายยาจากเครื่องจริง ยอดราคาและสต็อกตรวจซ้ำที่เซิร์ฟเวอร์ หากมีการเปลี่ยนราคา/สินค้าหมด แอปจะให้กลับมาตรวจตะกร้า หากการเชื่อมต่อขัดข้อง ให้อยู่หน้าชำระเงินและลองยืนยันรายการเดิมอีกครั้งเพื่อป้องกันการตัดสต็อกซ้ำ

## ข้อมูลสินค้าที่ใช้งาน

ฐานข้อมูล `backend/data/demo.sqlite3` เก็บข้อมูลถาวรแม้รีสตาร์ตเซิร์ฟเวอร์ นำเข้าสินค้า 27 รายการจาก `backend/seed_products.json` เฉพาะครั้งแรก พร้อมสต็อกเดโมรายการละ 20 ชิ้น หลังจากนั้นให้แก้สินค้าผ่านแอดมิน การแก้ `lib/data/medicine_data.dart` หรือ seed จะไม่เขียนทับฐานข้อมูลที่มีอยู่

รูปในหน้าแอดมินเลือกจาก `assets/images/` หากเพิ่มไฟล์รูปใหม่ ให้เพิ่มในโฟลเดอร์นี้แล้วรัน/บิลด์ Flutter ใหม่เพื่อบรรจุไฟล์รูปด้วย หลังบ้านและแอปควรใช้ไฟล์ assets ชุดเดียวกัน

เมื่อ API ไม่ทำงาน หน้าร้านแจ้งสถานะและยังแสดงข้อมูลที่โหลดไว้/ข้อมูลตั้งต้นได้ แต่การสั่งซื้อจะไม่สำเร็จจนกว่าหลังบ้านจะตอบกลับ

## iOS Simulator และ iPhone

Simulator บน Mac ใช้หลังบ้านค่าเริ่มต้นได้:

```sh
flutter devices
flutter run -d <simulator-id>
```

บนเครื่องที่ใช้ทดสอบ Xcode 27 มีปัญหา `lipo -verify_arch` เมื่อบิลด์ Simulator รวม `arm64 x86_64` แม้ไฟล์มีทั้งสองสถาปัตยกรรม หาก `flutter build ios --simulator` แจ้งว่าไม่มี architecture ให้ใช้ `flutter run -d <simulator-id>` ข้างต้นซึ่งเลือกรุ่นอุปกรณ์โดยตรง ตรวจแล้วรันบน iPhone 17 Simulator ได้ โดยไม่ต้องแก้ Flutter SDK หรือตัดการรองรับ Intel ออกจากโปรเจกต์

สำหรับ iPhone จริง ให้ Mac และ iPhone อยู่ Wi-Fi เดียวกัน เปิดหลังบ้านให้รับการเชื่อมต่อในเครือข่าย:

```sh
python3 backend/server.py --host 0.0.0.0
scutil --get LocalHostName
```

นำชื่อที่ได้มาต่อ `.local` เช่น `MacBook.local`:

```sh
flutter run -d <iphone-device-id> --dart-define=API_URL=http://MacBook.local:8765
```

เชื่อมต่อและ Trust iPhone เปิด Developer Mode แล้วเลือก Signing Team ของ Runner ใน `ios/Runner.xcworkspace` ก่อนรันครั้งแรก อนุญาต Local Network เมื่อแอปถาม และอนุญาต Python ผ่าน Firewall บน Mac หากถาม ถ้าแอปโหลดก่อนอนุญาตเครือข่าย ให้กดอัปเดตสินค้าอีกครั้ง `127.0.0.1` บน iPhone คือโทรศัพท์เอง จึงใช้เชื่อม Mac ไม่ได้

`API_URL` เปลี่ยนด้วย `--dart-define` ต้องหยุดแล้วรันแอปใหม่ ไม่ใช่เพียง Hot Reload เซิร์ฟเวอร์นี้สำหรับเดโมในเครื่อง/เครือข่ายที่ไว้ใจเท่านั้น ไม่ควรเปิดพอร์ตสู่อินเทอร์เน็ต
